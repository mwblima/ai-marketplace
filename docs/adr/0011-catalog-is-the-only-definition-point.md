# ADR-0011 — The catalog entry is the only place an artifact is defined

- **Status:** Accepted
- **Date:** 2026-08-12

## Context

ADR-0003 established that the catalog is the single source of truth and that
`marketplace.json` is generated from it. The first implementation only went half way: it
generated `marketplace.json`, but left `plugin.json` and every `SKILL.md` frontmatter block
to be written by hand.

That put the same description in three hand-maintained places:

```
catalog/company/code-review.yaml                  hand-written
plugins/code-review/.claude-plugin/plugin.json    hand-written  ← duplicate
plugins/code-review/skills/code-review/SKILL.md   hand-written  ← duplicate
.claude-plugin/marketplace.json                   generated
```

Nothing checked that the three agreed. The failure mode is quiet and bad: an author fixes
the description in the catalog, the site and the install UI show the new text, and the model
keeps triggering on the stale text in `SKILL.md` — which is the copy that actually drives
activation. Three edits per wording change is also exactly the kind of friction that pushes
contributors back to keeping their own local copy.

## Decision

**One artifact is defined in one file: its catalog entry.** Everything else is generated by
`scripts/build.mjs`, committed, and verified by CI with `--check`.

Generated from the catalog entry:

| Output | Fields |
|---|---|
| `.claude-plugin/marketplace.json` | the entry, minus governance-only fields |
| `plugins/<name>/.claude-plugin/plugin.json` | `name`, `version`, `description`, `author` |
| `plugins/<name>/skills/<skill>/SKILL.md` frontmatter | `name`, `description` |
| `plugins/<pack>/.claude-plugin/plugin.json` | pack manifest (ADR-0005) |
| `docs/data/index.json` | site search index (ADR-0006) |

An author writes exactly two things: the catalog YAML, and the **body** of each `SKILL.md`
below the frontmatter. The build replaces the frontmatter block and leaves the body byte for
byte as written.

`author` is resolved from `owner_team` through a `teams` map in `marketplace.config.json`, so
a team's contact address is also defined once rather than repeated in every manifest.

**Multi-skill plugins** declare a per-skill description under `skills.<name>.description` in
the catalog entry. When a plugin ships exactly one skill, the entry's own description is
used. A plugin shipping several skills without per-skill descriptions is a build error, not
a silent fallback — guessing which description belongs to which skill is precisely the kind
of quiet wrongness this ADR exists to remove.

**Generated files are committed, not produced at install time.** The marketplace entry points
the client directly at `plugins/<name>/`, so that directory has to be complete and correct in
the repository. `node scripts/build.mjs --check` fails CI when a committed output does not
match what the catalog produces.

## Consequences

- A description now cannot drift between search, install UI, and model activation. They are
  the same string by construction.
- One file per artifact keeps concurrent contributions conflict-free (the reason ADR-0003
  rejected a monolithic catalog), and now that file is genuinely the only one to edit.
- Editing generated frontmatter by hand silently loses the edit on the next build. CI's
  `--check` catches it in the PR rather than after merge, and the PR template says where to
  make the change instead.
- The build gained real logic and can now fail with a domain error (the multi-skill case),
  where before it only wrote files. That is an acceptable trade for removing a class of
  silent divergence.

## Alternatives considered

- **Keep the three copies and validate that they match** — rejected. It catches the
  divergence but keeps the three edits, so it fixes the symptom and not the friction.
- **Generate at install time instead of committing** — impossible without changing the
  distribution model: the client reads `plugins/<name>/` straight from the repository.
- **Drop `plugin.json` and let the marketplace entry carry everything** — rejected. The
  manifest is what makes a plugin directory self-describing when read outside this
  repository, and dropping it would break the `git clone` install path for other tools.
